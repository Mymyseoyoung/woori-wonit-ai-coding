### **[문제 해결 리포트] 입금 버튼 이벤트 미작동 및 잔액 표시 오류**

**1. 이슈 제목**
페이지 로드 시 입금 로직이 즉시 실행되며, 정작 버튼 클릭 시에는 동작하지 않고 잔액 업데이트 시 에러가 발생함.

**2. 발생 경로**

1. 페이지 로드 직후 사용자 조작 없이 입금 로직이 강제 실행됨.
2. 이후 화면의 '입금' 버튼 클릭 시 아무런 반응이 없음.
3. 입금 후 잔액 텍스트가 갱신되지 않고 콘솔에 DOM 참조 에러가 발생함.

**3. 디버깅**

- **이벤트 바인딩 상태 확인:** 입금 버튼의 `click` 이벤트에 함수가 아닌 `undefined`가 할당되어 있음을 확인.
- **DOM 참조 에러 추적:** `app.js`에서 변수 할당 시 `document.getElementById("blance")`를 콘솔에 출력한 결과 `null`이 반환됨을 파악.

**4. 문제 해결 과정**

- **발생 위치:** `app.js` 이벤트 리스너 등록부(139-142 라인) 및 DOM 요소 할당부(78 라인)
- **문제 원인:** 이벤트 리스너 등록 시 콜백 함수에 괄호를 붙여 즉시 실행되게 만들었으며, 요소 ID 선택 시 철자 오타(`blance`)가 발생함.
- **해결 방법:**
    1. `depositBtn.addEventListener("click", handleDeposit());` 코드를 `handleDeposit` (괄호 제거)으로 변경하여 클릭 시점에만 실행되도록 조치.
    2. `document.getElementById("blance");`를 실제 HTML ID와 일치하도록 `"balance"`로 오타 수정.

**5. 사이드 이펙트에 대한 대책**

- **예측 가능한 사이드 이펙트:** 클릭 이벤트가 정상 작동하기 시작하면서, 기존에 드러나지 않았던 `handleDeposit` 내부의 로직 버그(예: 금액이 문자열로 결합되거나 음수가 입력되는 현상)가 노출될 수 있음.
- **해결 방안:**
    - **단기 대책:** 전역 검색을 통해 `"blance"` 오타가 다른 곳에 쓰였는지 확인하여 일괄 수정하고, 입력값이 `Number`형으로 잘 변환되는지 점검.
    - **장기 대책 (시나리오):** ESLint를 도입하여 정의되지 않은 콜백 함수 실행 오용 및 DOM ID 오타 등을 빌드 단계에서 사전에 차단하도록 워크플로우를 개선함.

### 버그 리포트 2

### **[문제 해결 리포트] 환율 정보 "불러오는 중..." 무한 대기 현상**

**1. 이슈 제목**
환율 표시 영역이 업데이트되지 않고 "불러오는 중..." 텍스트 상태로 멈춰 있는 버그.

**2. 발생 경로**
페이지 로드 후 정상 대기 시간(0.5초)이 지나도 실제 환율 데이터(예: 1384원)로 갱신되지 않음.

**3. 디버깅**

- **비동기 로직 검증:** `fetchExchangeRate` 함수는 0.5초 후 정상적으로 데이터를 반환하도록 설계되어 있음을 확인.
- **호출부 추적:** 실제 화면을 업데이트하는 `displayExchangeRate()` 함수가 선언만 되어 있고, 코드 내에서 한 번도 호출(실행)되지 않았음을 파악.

**4. 문제 해결 과정**

- **발생 위치:** `app.js` 하단 초기 렌더링 실행부
- **문제 원인:** 화면 갱신 함수가 실행되지 않아 초기 하드코딩된 상태값("불러오는 중...")이 그대로 남음.
- **해결 방법:** 초기 잔액을 그려주는 `renderBalance();` 코드 바로 하단에 `displayExchangeRate();` 호출을 추가 삽입하여 페이지 로드 시 갱신되도록 조치함.

**5. 사이드 이펙트에 대한 대책**

- **예측 가능한 사이드 이펙트:** 함수가 실행되면서 비동기 호출이 발생하므로, 네트워크 에러나 서버 지연 시 스크립트 실행이 중단될 위험이 있음.
- **해결 방안:**
    - **단기 대책:** 해당 함수 내부에 `try-catch` 블록을 추가하여, 통신 실패 시 "환율 갱신 실패"라는 대체(Fallback) 텍스트를 띄우도록 예외 처리.
    - **장기 대책 (시나리오):** 통신 지연에 대비해 로딩 스피너나 스켈레톤 UI를 도입하여 UX를 개선함.

### 버그 리포트 3

### **[문제 해결 리포트] 환율 영역 '[object Promise]' 노출 버그**

**1. 이슈 제목**

환율 표시 영역에 실제 금액 대신 비동기 객체 문자열(`[object Promise]원`)이 렌더링되는 문제.

**2. 발생 경로**

1. 페이지 로드 후 `displayExchangeRate()` 함수 실행.
2. 화면 하단 환율 영역에 숫자(예: 1384원) 대신 `[object Promise]원` 텍스트가 출력됨.

**3. 디버깅**

- `app.js`에서 `const rate = fetchExchangeRate();` 실행 직후 변수 `rate`의 값을 콘솔에 출력.
- 값이 숫자가 아닌 `Promise { <pending> }` 객체임을 확인. 이를 DOM의 `textContent`에 할당하려다 자바스크립트 엔진이 강제로 문자열 변환을 일으킨 것으로 파악.

**4. 문제 해결 과정**

- **발생 위치:** `app.js` (108~109 라인) `displayExchangeRate` 함수 내부
- **문제 원인:** 비동기 함수인 `fetchExchangeRate()`의 처리가 끝날 때까지 기다리지 않고, 즉시 반환된 Promise 객체를 그대로 화면에 출력하려 함.
- **해결 방법:** 반환값을 동기적으로 기다리도록 `await` 키워드를 추가함.
    - 수정 전: `const rate = fetchExchangeRate();`
    - 수정 후: `const rate = await fetchExchangeRate();` (함수 선언부에 `async`가 명시되어 있어야 함)

**5. 사이드 이펙트에 대한 대책**

- **예측 가능한 사이드 이펙트:** `await` 사용 시 환율 데이터를 받아올 때까지 해당 함수의 실행이 일시 정지(Blocking)되므로, 응답이 늦어지면 내부의 다른 UI 렌더링 로직도 함께 지연될 수 있음.
- **해결 방안:**
    - **단기 대책:** 환율 렌더링 로직을 완전히 독립된 함수로 분리해, 메인 UI(잔액 조회 등) 렌더링 흐름에 영향을 주지 않도록 병렬 처리함.
    - **장기 대책 (시나리오):** API 응답 실패나 무한 지연에 대비해 `try-catch` 블록을 추가하고, 에러 발생 시 "환율 정보 조회 실패"라는 기본(Fallback) 텍스트를 노출하도록 예외 처리를 강화함.

### 버그 리포트 4

### **[문제 해결 리포트] 이체 모달창 표시 위치 오류 및 노출 불가 버그**

**1. 이슈 제목**

'이체' 버튼 클릭 시 모달창이 화면 전체를 덮지 못하고 화면 밖이나 일반 문서 흐름에 묻혀 보이지 않는 UI 렌더링 문제.

**2. 발생 경로**

1. 페이지 로드 후 화면의 '이체' 버튼을 클릭.
2. JavaScript의 클릭 이벤트는 정상 작동하나, 모달창이 화면 중앙에 팝업 형태로 나타나지 않음을 확인.

**3. 디버깅**

- **JS 로직 검증:** `app.js`에서 클릭 이벤트 리스너와 `modalOverlay.classList.remove("hidden");` 코드가 정상적으로 실행되어 DOM 상에서 클래스가 지워지는 것을 확인. (스크립트 문제는 아님)
- **CSS 요소 검사:** 브라우저 개발자 도구(F12)로 `.modal-overlay` 클래스를 검사한 결과, `top`, `left`, `z-index` 속성은 있으나 이를 화면에 고정할 `position` 속성이 누락되어 일반 레이아웃 흐름(static)에 따라 배치되고 있음을 파악함.

**4. 문제 해결 과정**

- **발생 위치:** `style.css` (101~110 라인) `.modal-overlay` 선택자
- **문제 원인:** 모달 오버레이를 브라우저 뷰포트 전체에 덮어씌우기 위한 `position: fixed;` 속성이 누락됨. 이로 인해 100% 크기 지정이나 위치 지정(top/left)이 제대로 동작하지 않음.
- **해결 방법:** `.modal-overlay` CSS 속성에 `position: fixed;`를 추가하여 모달이 뷰포트(화면)를 기준으로 최상단에 고정되도록 수정함.CSS
    
    ```
    .modal-overlay {
      position: fixed; /* 추가된 핵심 속성 */
      z-index: 500;
      top: 0;
      /* 이하 기존 코드 유지 */
    }
    ```
    

**5. 사이드 이펙트에 대한 대책**

- **예측 가능한 사이드 이펙트:** 모달이 정상적으로 화면을 덮게 되었으나, 사용자가 모달 밖의 배경을 스크롤할 경우 뒤쪽의 본문 페이지가 함께 스크롤되는 현상(이중 스크롤)이 발생할 수 있음.
- **해결 방안:**
    - **단기 대책:** 모달 요소 태그가 DOM 트리의 최상위(`<body>` 바로 아래)에 위치하는지 확인하여, 다른 부모 요소의 CSS 속성 간섭을 받지 않도록 구조를 점검함.
    - **장기 대책 (시나리오):** JS의 모달 열기/닫기 로직에 `document.body.style.overflow = "hidden"` (또는 관련 클래스 토글) 처리를 추가하여, 모달이 떠 있는 동안 뒷배경 스크롤을 차단(Scroll Lock)하는 UX 개선을 적용함.
